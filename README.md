使用react+ts搭建项目，支持路由。实现的项目功能是类似微信阅读。

首页是 home.png
支持导入书籍，导入的是markdown文件

点击打开读书内容页后是content.png 当前的是左右点击上下页翻页，但是我不需要点击上下页，只需要上下滑动就行。

也不用左右的布局。

内容页主要要实现的功能是：
1. 左侧有目录列表，类似石墨文档的左侧目录
2. 选中一串文本之后需要有标记的功能
可标记为疑问、重点（可以选择颜色）、写想法，效果类似image.png

你可以询问我一些问题之后决定怎么具体实现，问题和回答需要写入到该文件。

## 实现确认问题

### Q1. 技术栈
推荐：Vite + React + TypeScript + React Router + Less。
是否按此搭建？还是有指定框架（如 Next.js）？

**回答：** 不使用 Next.js。采用 Vite + React + TypeScript + React Router + Less。

### Q2. 首页范围
参考 home.png 有搜索、热搜、大家都在看、登录等。
本项目首页是否简化为：
- 展示已导入书籍列表（书架）
- 提供「导入 Markdown」入口
搜索 / 热搜 / 登录 /「大家都在看」是否需要做？做到什么程度（真实功能 / 仅 UI 占位）？

**回答：** 简化为书架 + 导入 Markdown。不做搜索 / 热搜 / 登录 /「大家都在看」。

### Q3. Markdown 导入与书籍元信息
导入时：
- 书名、作者从哪里来？（文件名 / Markdown  frontmatter / 导入时手动填写）
- 是否需要封面图？（可选上传 / 默认占位图）
- 是否支持一次导入多本？是否支持删除书籍？

**回答：** （用户未单独说明，按合理默认）书名优先取 Markdown 首个 `#` 标题，否则用文件名；作者取 frontmatter `author`，无则「未知作者」；默认占位封面；支持多文件导入与删除。

### Q4. 数据持久化
书籍内容、目录、划线/想法是否需要刷新后仍保留？
若需要，优先用浏览器本地存储（localStorage / IndexedDB），还是需要后端？

**回答：** 需要持久化，写入本项目本地文件（通过本地 Node API 读写 `data/` 目录）。

### Q5. 内容页布局与主题
- 阅读区：单栏纵向滚动（无左右双栏、无上下页按钮），是否正确？
- 左侧目录：默认展开还是可折叠？是否跟随滚动高亮当前章节？
- 主题：默认深色（参考 content.png）还是浅色？是否需要明暗切换？

**回答：** 单栏纵向滚动确认。左侧目录默认展开，滚动高亮当前章节。默认浅色，支持切换深色。

### Q6. 目录如何生成
目录是否根据 Markdown 的 `#` / `##` / `###` 自动生成？是否需要支持多级目录嵌套？

**回答：** 根据 `#` 等标题自动生成，支持多级嵌套。

## GitHub Pages 部署

线上地址（自定义域名）：https://reSelf.1cor1514.site

GitHub Pages 为**静态只读**站点：
- 书单与正文直接读取仓库中的 `public/default-books/`
- 不写入浏览器本地存储
- 不支持导入、删除、划线/想法（本地 `npm run dev` 仍可完整使用）

### 1. 仓库设置

1. 打开 GitHub 仓库 `Settings` → `Pages`
2. **Source** 选择 `GitHub Actions`
3. **Custom domain** 填写：`reSelf.1cor1514.site`
4. 建议勾选 **Enforce HTTPS**（DNS 生效后可启用）

### 2. DNS 配置

在域名 `1cor1514.site` 的 DNS 服务商添加：

| 类型 | 主机记录 | 记录值 |
| --- | --- | --- |
| CNAME | `reSelf` | `gulinga.github.io` |

（当前仓库 remote 为 `guLinga/seBook`，记录值使用 `gulinga.github.io`）

### 3. 自动部署

推送到 `main` 分支后，Actions 工作流 `Deploy GitHub Pages` 会自动构建并发布。

本地也可手动构建：

```bash
npm run build:pages
```

产物在 `dist/`，包含 `CNAME` 与 SPA 用的 `404.html`。

要增删线上书单：修改 `public/default-books/` 下的 Markdown 与 `manifest.json`，提交后重新部署即可。
